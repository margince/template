# Default VM Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The template ships a default `production` environment for one Linux VM (EC2 or similar) through the `host` adapter, so every new instance can deploy after filling in three values.

**Architecture:** Changes to `scripts/deploy-init.sh` (placeholders), `scripts/deploy/host.sh` (`check` guard), `scripts/new-instance.sh` (regenerate `deploy/production/` per instance), the template's own `deploy/production/` and `instance.yaml`, and the lifecycle test and docs.

**Tech Stack:** Bash (macOS 3.2 and Linux 5), GNU Make, the Go CLI in `scripts/cli`.

**Spec:** `docs/superpowers/specs/2026-09-24-client-instance-template-design.md`, Section 9.8 (binding), with 9.6 and 9.7.

## Global Constraints

- Placeholders: `HOST_SSH=` and `HOST_DOMAIN=` empty; admin email `admin@example.com`.
- `check` refusal messages name the file to edit: `deploy/<env>/host.env` for HOST_SSH/HOST_DOMAIN, `deploy/<env>/config/margince.yaml` for the admin email.
- `deploy/` stays instance-owned (not in `.template-owned`).
- Scripts: `set -euo pipefail`, source `scripts/lib.sh`, Bash 3.2 compatible; tests use stubs, no network, stdin from `/dev/null`.
- No private names (`make check-public`); every documented `make` target exists (`make check-docs`).
- Commits: Conventional Commits, ending with exactly `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
- After every task: `make test-scripts </dev/null`, `make test-cli`, `make check-instance`, `make check-docs`, `make check-public` pass.

## Review Focus

1. A new instance created with no DOMAIN/SSH has a valid `instance.yaml` and passes `make check`, and `make deploy ENV=production` stops at `check` with a message naming `deploy/production/host.env`.
2. `make new-instance` with DOMAIN/SSH/ADMIN_EMAIL produces a deployable `deploy/production/` with those values and the instance's display name.
3. `make deploy-init` with DOMAIN/SSH still behaves exactly as before.

### Task 1: Placeholders, the check guard, the template default, and new-instance

**Files:**
- Modify: `scripts/deploy-init.sh`, `scripts/deploy-init.test.sh`
- Modify: `scripts/deploy/host.sh` (`check`), `scripts/deploy/host.test.sh`
- Modify: `scripts/new-instance.sh`, `scripts/new-instance.test.sh`, `Makefile` (`new-instance` passes DOMAIN, SSH, ADMIN_EMAIL; help text)
- Create: `deploy/production/` (generated by the updated `make deploy-init ENV=production` in the template); Modify: `instance.yaml`

Requirements (spec Section 9.8):
- `deploy-init`: DOMAIN, SSH, ADMIN_EMAIL optional for `host`. Missing values → `HOST_SSH=` / `HOST_DOMAIN=` empty with a comment line above each saying what to enter (e.g. `# user@host of the server, e.g. ubuntu@203.0.113.10`), admin email `admin@example.com` with a comment to change it; the next-steps output then starts with "fill in deploy/<env>/host.env and the admin email in deploy/<env>/config/margince.yaml". Given values behave exactly as today (existing tests stay green).
- `host.sh check`: fail while HOST_SSH or HOST_DOMAIN is empty (message names `deploy/<env>/host.env`) or `bootstrap_admin.email` in `deploy/<env>/config/margince.yaml` is `admin@example.com` (message names that file). Read the email with a minimal line match on the `email:` key under `bootstrap_admin:`; test both quoted and unquoted forms as deploy-init writes them.
- `new-instance`: after creating the instance, remove the template's `deploy/` from it, remove any `deploy:` block from the fresh `instance.yaml` (new-instance writes it fresh today — keep it without `deploy:`), then run the instance's own `scripts/deploy-init.sh` with `ENV=production` and the given DOMAIN/SSH/ADMIN_EMAIL, and include `deploy/` and `instance.yaml` in the creation commit. The new instance passes `make check-instance`.
- Template: run the updated `make deploy-init ENV=production` in the template to produce `deploy/production/` and the `instance.yaml` entry; commit them. `make check-instance` passes in the template.
- Tests: deploy-init placeholder output (host.env, email, next steps); host check refusals (each of the three) and acceptance when filled; new-instance with and without DOMAIN/SSH/ADMIN_EMAIL (files, values, display name in workspace, instance.yaml has `production: { adapter: host }`, `cli check` passes).
